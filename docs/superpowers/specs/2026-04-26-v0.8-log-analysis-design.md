# v0.8.0 — Log-file analysis

**Date:** 2026-04-26
**Status:** Approved, pending implementation plan
**Target version:** v0.8.0

## Goal

Add a new `seo-audit logs <path>` subcommand that parses bot-traffic data
from web-server / CDN access logs and joins it against the most recent
persisted crawl to surface findings invisible to single-snapshot audits.

The subcommand operates in two layers:

- **Layer A — Standalone bot summary.** Runs unconditionally on any
  log input. Verified bot hits aggregated by URL, status, and bot
  identity. The "what did crawlers actually do?" baseline.
- **Layer B — Joined to a persisted crawl.** Auto-activates when a
  prior `seo-audit` crawl exists for the same host. Surfaces three
  high-value joined findings:
  - **F2 — Orphan pages.** URLs bots visit that aren't in the
    internal link graph at all.
  - **F3 — Stale priorities.** Top-PageRank URLs that bots haven't
    crawled in the log window.
  - **F4 — Status mismatches.** URLs the audit says are 200 but bots
    saw 4xx/5xx in the window.

Closes the largest remaining technical-SEO feature gap against
Sitebulb and Screaming Frog Log Analyzer, and is the v0.8 differentiator:
log analysis without server access, hermetic across environments, and
agent-friendly by design.

## Non-goals

- **No F1 (crawl budget waste) in v0.8.** Highest-quoted use case but
  also the noisiest finding without real-world threshold calibration.
  Defer to v0.9 once we have feedback on real logs.
- **No multi-file / glob input.** `seo-audit logs ./logs/*.log` is a
  follow-up. v0.8 takes one path or a stream.
- **No time-series visualization.** Report is point-in-time over a
  single log window. Multi-window comparisons are a follow-up.
- **No IP geolocation.** Out of scope; orthogonal feature.
- **No log-collector integration.** The user runs the export from
  their CDN/host themselves; the tool only consumes a file or stream.
- **No persisted DNS cache.** In-memory only by design (privacy).
- **No raw IPs in any output.** Counts only. Privacy commitment.
- **No phone-home telemetry.** Matches the rest of the tool.

## Decisions

| # | Question | Decision |
|---|----------|----------|
| 1 | Scope | Layer A always, Layer B when a persisted crawl exists. |
| 2 | Bot verification | On by default, in-memory cached, with reverse-DNS → forward-DNS suffix match. Opt-out via `--no-verify-bots`. |
| 3 | Entry point | New `logs` subcommand: `seo-audit logs <path> --site <url>`. Standalone analysis; auto-joins to the most recent persisted crawl for that host. |
| 4 | Findings (Layer B) | F2 (orphans) + F3 (stale priorities) + F4 (status mismatches). F1 deferred. |
| 5 | DNS-restricted environments | Single startup probe; on failure, auto-disable verification, emit `LOG_DNS_UNAVAILABLE` issue, continue with all hits as `unverifiedBotHits`. |
| 6 | Library input | `analyzeLogs(input: string \| Readable, options)`. Stream or path. CLI's `-` path maps to stdin. |
| 7 | Progress | Structured `LogAnalysisProgressEvent` callback. CLI shows TTY-only stderr line; opt-out via `--no-progress` / `SEO_AUDIT_NO_PROGRESS=1` (same convention as v0.6). |
| 8 | Privacy | No raw IPs in output. DNS cache in-memory only. No telemetry. |
| 9 | Schema stability | `LogAnalysisReport` is a stable shape from v0.8 onward — additive only without a major version bump. |
| 10 | Exit codes | 0 success / 1 input or parse error / 2 `--fail-on` triggered. Same as the main audit. |

### Open-source upgrade considerations

The package is published to npm as `@davo20019/seo-audit` (current v0.7.0 → planned v0.8.0).

- **No new dependencies.** Streaming parser uses `node:readline`; DNS uses `node:dns/promises`. Format detection and parsers are pure regex / `JSON.parse`.
- **No breaking changes.** New subcommand and new public type. Existing `analyzeSite`/`AnalyzeOptions`/`SiteReport` shapes unchanged.
- **No new `--fail-on` regression risk** for users who don't run `seo-audit logs`. The new issue codes (`LOG_*`) only fire from the new subcommand.
- **Hermetic tests.** All log fixtures committed under `tests/fixtures/logs/`. DNS verification mocked via dependency injection. CI sets `SEO_AUDIT_NO_DNS=1` defensively. No test issues real network calls.

## Public API

### CLI

```
seo-audit logs <path>            Analyze a log file. Use "-" for stdin.

  --site <url>                   Required. Host whose persisted crawl to join against.
  --format <fmt>                 combined | json | cloudflare | fastly. Default: auto-detect from first 5 non-empty lines.
  --no-verify-bots               Skip reverse-DNS verification (fast, includes spoofers).
  --since <iso>                  Filter log entries to timestamps ≥ this ISO date.
  --until <iso>                  Filter log entries to timestamps < this ISO date.
  --json                         Print raw JSON instead of text report.
  --output <path>                Write JSON report to file.
  --html-report <path>           Write polished HTML report to file.
  --pdf-report <path>            Write PDF report to file (existing convention).
  --no-progress                  Disable interactive stderr progress.
  --fail-on <severity>           Exit non-zero if issues at <severity> are present.
```

### Library

```ts
import { analyzeLogs } from "@davo20019/seo-audit";

const report = await analyzeLogs(input, {
  site: "https://example.com",
  format: "auto",
  verifyBots: true,
  since: "2026-04-19T00:00:00Z",
  until: "2026-04-26T00:00:00Z",
  onProgress: (event) => { /* … */ }
});
// input:
//   - string: path to a file
//   - "-":    sentinel meaning "read process.stdin"
//   - NodeJS.Readable: a stream the caller has already opened
```

### New types (in `src/types.ts`)

```ts
export interface LogTimeWindow {
  earliest: string;   // ISO
  latest: string;     // ISO
  durationHours: number;
}

export interface VerifiedBot {
  name:
    | "googlebot"
    | "bingbot"
    | "applebot"
    | "duckduckbot"
    | "claudebot"
    | "gptbot"
    | "perplexitybot"
    | "other";
  hits: number;
  uniqueUrls: number;
  uniqueIps: number;             // count only — never the IPs themselves
}

export interface OrphanFinding {
  url: string;
  hits: number;
  bots: string[];
  firstSeen: string;
  lastSeen: string;
}

export interface StaleFinding {
  url: string;
  pageRank: number;
  daysSinceLastCrawl: number | null;   // null = not seen in window at all
  hitsInWindow: number;
}

export interface StatusMismatchFinding {
  url: string;
  crawlStatus: number;                 // always 200 by definition
  logStatuses: Record<number, number>; // status code → count
  worstStatus: number;
  hits: number;
}

export interface LogAnalysisBaseline {
  crawledAt: string;
  pages: number;
  daysOld: number;
}

export interface LogAnalysisReport {
  source: string;                       // file path or "stdin"
  format: string;                       // detected/specified
  totalLines: number;
  parseErrors: number;
  timeWindow: LogTimeWindow;
  bots: VerifiedBot[];
  spoofedHits: number;                  // claimed bot UA, failed verification
  unverifiedBotHits: number;            // claimed bot UA, verification unavailable
  baselineCrawl: LogAnalysisBaseline | null;
  orphans: OrphanFinding[];                  // F2
  stalePriorities: StaleFinding[];           // F3
  statusMismatches: StatusMismatchFinding[]; // F4
  issues: Issue[];
}

export type LogAnalysisProgressEvent =
  | { phase: "parse-start"; format: string }
  | { phase: "parse-progress"; linesRead: number; bytesRead: number }
  | { phase: "verify-start"; uniqueBotIps: number }
  | { phase: "verify-progress"; verified: number; total: number }
  | { phase: "join-start" }
  | { phase: "complete" };

export interface AnalyzeLogsOptions {
  site: string;
  format?: "auto" | "combined" | "json" | "cloudflare" | "fastly";
  verifyBots?: boolean;          // default: true
  since?: string;                // ISO
  until?: string;                // ISO
  onProgress?: (event: LogAnalysisProgressEvent) => void;
  dnsResolver?: DnsResolver;     // dependency-injection seam for tests
}
```

`Issue` and `Severity` already exist; `LOG_*` codes use the same shape.

## Components

### `src/logs/parse.ts`

Pure module. Streaming parser. Format detector + four format-specific
parsers. Emits `RawLogEntry { ip, timestamp, method, url, status, userAgent }`
via async iterator.

Public exports:
```ts
export function detectLogFormat(sampleLines: string[]): LogFormat;
export async function* parseLogStream(
  input: Readable,
  format: LogFormat
): AsyncIterable<RawLogEntry>;
```

Auto-detect reads up to the first 5 non-empty lines, never the whole stream.

### `src/logs/verify.ts`

Pure-ish (depends on `node:dns/promises`). Reverse-DNS → forward-DNS →
hostname suffix match. Built-in `Map<ip, BotVerdict>` cache.

Public exports:
```ts
export type DnsResolver = {
  reverse: (ip: string) => Promise<string[]>;
  resolve4: (host: string) => Promise<string[]>;
  resolve6: (host: string) => Promise<string[]>;
};

export interface VerifyOptions {
  dnsResolver?: DnsResolver;          // tests inject mock; default uses node:dns
  concurrency?: number;               // default 50
  timeoutMs?: number;                 // default 2000 per IP
}

export interface BotVerdict {
  bot: VerifiedBot["name"] | null;    // null = spoofer
  verified: boolean;                  // false = lookup failed/timed out
}

export async function probeDnsAvailable(resolver: DnsResolver): Promise<boolean>;
export function createBotVerifier(opts: VerifyOptions): {
  verify(ip: string, claimedBot: string): Promise<BotVerdict>;
};
```

`probeDnsAvailable` runs one cheap lookup against `8.8.8.8` (or similar)
to detect DNS-restricted environments at startup. The orchestrator uses
its result to decide whether to enable verification or fall back to
`verifyBots: false` semantics with a `LOG_DNS_UNAVAILABLE` warning.

### `src/logs/aggregate.ts`

Pure. Streaming reducer over verified entries. Builds `Map<url, UrlAgg>`
and the per-bot summary.

```ts
export interface UrlAgg {
  hits: number;
  bots: Set<string>;
  statusCounts: Map<number, number>;
  firstSeen: string;
  lastSeen: string;
}

export function createAggregator(): {
  add(entry: VerifiedLogEntry): void;
  finish(): { urls: Map<string, UrlAgg>; bots: VerifiedBot[]; timeWindow: LogTimeWindow };
};
```

### `src/logs/findings.ts`

Pure. Three finding functions over `(siteReport: SiteReport, agg)`.

```ts
export function findOrphans(agg: AggResult, crawl: SiteReport): {
  findings: OrphanFinding[]; issues: Issue[];
};
export function findStalePriorities(agg: AggResult, crawl: SiteReport, windowEnd: string): {
  findings: StaleFinding[]; issues: Issue[];
};
export function findStatusMismatches(agg: AggResult, crawl: SiteReport): {
  findings: StatusMismatchFinding[]; issues: Issue[];
};
```

### `src/logs/index.ts`

Public `analyzeLogs(input, options)` orchestrator. ~80 lines.

### `src/cli.ts` changes

New `logs` subcommand branch alongside the existing `diff` branch.
Reuses existing `--output` / `--html-report` / `--pdf-report` /
`--fail-on` / `--no-progress` plumbing.

### `src/report.ts` changes

`renderLogAnalysisReport(report: LogAnalysisReport): string` — HTML
section. Mirror text formatter `formatLogAnalysisReport(...)` lives
in `src/cli.ts` next to the other text formatters.

## Data flow

```
log file or Readable
    │
    ▼
detectLogFormat(first 5 non-empty lines) ──▶ parser
    │
    ▼  RawLogEntry stream
botUaFilter (UA matches one of N known bot signatures)
    │
    ▼  ClaimedBotEntry stream
probeDnsAvailable() once at startup
    │
    ├─ available ──▶ verifier (cached, concurrency-limited)
    └─ unavailable ──▶ pass-through; mark all as unverifiedBotHits
    │
    ▼  VerifiedLogEntry stream (or pass-through)
aggregator.add(entry) for each
    │
    ▼  AggResult { urls, bots, timeWindow }
loadPersistedCrawl(site)  ◀── reuse src/persist.ts
    │
    ├─ found    ──▶ findOrphans, findStalePriorities, findStatusMismatches
    └─ missing  ──▶ Layer B disabled; baselineCrawl = null
    │
    ▼
LogAnalysisReport (with issues[])
```

## Issue codes

All low severity. Integrate with `--fail-on low`. Recommendations included.

| Code | When | Recommendation summary |
|---|---|---|
| `LOG_ORPHAN_PAGE` | Bot-visited URL not in the persisted crawl's link graph. | Add an internal link to this URL or remove it from the index. |
| `LOG_STALE_PRIORITY_PAGE` | Top-100 PageRank URL not seen in the log window, or last-seen > 30 days. | Investigate why the page isn't being crawled; check robots, sitemap, internal links. |
| `LOG_STATUS_MISMATCH` | Persisted crawl says 200, log shows 4xx/5xx for bots in the window. | Investigate the time of the failures; possible CDN cache flush or transient outage. |
| `LOG_DNS_UNAVAILABLE` | DNS verification could not run. | Re-run from an environment with outbound DNS, or accept unverified results. |
| `LOG_BASELINE_STALE` | Persisted crawl is older than the log window's start. | Re-run a fresh `seo-audit` audit before trusting orphan/stale findings. |

## Findings detail (v0.8 thresholds)

- **Orphans (F2):** `urlAggregator.has(url) && !crawlPagesByUrl.has(url)`. When DNS was available, include only verified bots; spoofers excluded. When DNS was unavailable, include all claimed-bot hits (the `LOG_DNS_UNAVAILABLE` warning has already informed the user). Cap at 200 entries by hit count, descending.
- **Stale priorities (F3):** Take top-100 PageRank URLs from persisted crawl. For each, look up `urlAggregator[url].lastSeen`. Surface URLs with `null` (never seen) or `daysSinceLastCrawl > 30`. No cap (top-100 input, output ≤ 100).
- **Status mismatches (F4):** For URLs where persisted crawl's `page.status === 200`, look up `urlAggregator[url].statusCounts`. If any 4xx/5xx hit count > 0, emit. Cap at 200 by `worstStatus` hit count, descending.

## Time-window handling

Every report header (text + HTML) shows:
```
Log window:    2026-04-19 00:00 → 2026-04-26 00:00 UTC  (7 days)
Crawl baseline: 2026-04-25  (1 day old)
```

If `crawlBaseline.crawledAt < timeWindow.earliest` (crawl predates the
log window), emit a single `LOG_BASELINE_STALE` issue and surface the
warning prominently in the text/HTML output.

## Memory at scale

- **Streaming parser keeps zero log lines in memory.** `node:readline`
  over the input stream.
- **Aggregator** is the only thing that grows: `Map<url, UrlAgg>`.
  Realistic worst case: 100k unique URLs × ~200 bytes ≈ 20 MB. Fine.
- **DNS cache** is `Map<ip, BotVerdict>`, soft-capped at 100k entries
  via simple LRU eviction. Typical real-world logs have <5k unique
  bot IPs. No HyperLogLog or approximate counts in v0.8.

## Privacy commitments

- No raw IPs are written to any output (JSON, HTML, text, or stderr).
  `VerifiedBot.uniqueIps` is a count only.
- DNS cache is `Map`-only; never persisted to disk.
- No telemetry, no error reporting, no version-check pings.
- README's "Privacy" section will state these explicitly.

## Agent ergonomics

- **JSON-first.** `--json` writes the full `LogAnalysisReport` to stdout.
- **Schema stability** is documented in README starting v0.8.
- **`onProgress`** callback parity with v0.6's `analyzeSite`.
- **Stream input** in the library API.
- **Single-line stderr summary** after `--json` runs:
  `Log analysis: 7 days, 47k bot hits, 12 orphans, 3 stale priorities, 1 status mismatch.`
- **Predictable exit codes** matching the main audit (0 / 1 / 2).
- **No interactive prompts.** Same as the rest of the tool.

## Errors / edge cases

| Case | Behavior |
|---|---|
| `--site` missing | Error before parsing. Exit 1. |
| Persisted crawl absent for the host | Layer B cleanly disabled: `baselineCrawl: null`. Layer A still emits. |
| Format auto-detect fails | Error: "Could not auto-detect log format. Use --format to specify." Exit 1. |
| File not found / unreadable | Standard error. Exit 1. |
| Stdin closed mid-stream | Process whatever was read. `parseErrors` reflects truncated/garbled lines. |
| All entries fail bot UA filter (no bots in log) | Empty `bots[]`, empty findings, all metric counts zero. Not an error. |
| All bot entries fail verification (DNS works but verifier returns no matches) | Surface as `spoofedHits`. No findings emitted (no verified bots to attribute hits to). |
| DNS-restricted environment | `LOG_DNS_UNAVAILABLE` issue. All bot hits reported as `unverifiedBotHits`. Layer B still computes against the unverified set, with a note in the report. |
| `--since` / `--until` outside the actual log range | Filter empties the stream; surface as `parsedLines: 0` with a warning issue. |
| Invalid ISO dates in `--since` / `--until` | Error before parsing. Exit 1. |

## Testing strategy

### Unit tests

`tests/logs/parse.test.ts`:
- Combined Log Format: standard line, line with quoted UA containing spaces, line with non-200 status.
- JSON: pretty-printed and minified.
- Cloudflare: real-shape sample with `EdgeStartTimestamp` etc.
- Fastly: real-shape sample.
- Auto-detect against each format and against an unknown format.
- Truncated/garbled lines counted as `parseErrors`, parsing continues.

`tests/logs/verify.test.ts`:
- Mocked `DnsResolver`. Cases: real Googlebot IP (PTR → forward → match), spoofer (PTR resolves but forward doesn't match), DNS timeout (verdict `verified: false`).
- Cache hit on second lookup of same IP.
- Concurrency limit honored.

`tests/logs/aggregate.test.ts`:
- Single URL, multiple hits, verified bot.
- Multiple URLs, mixed bots, mixed statuses.
- Time-window inferred from min/max timestamps.

`tests/logs/findings.test.ts`:
- F2: URL in agg but not in crawl ⇒ orphan.
- F3: top-PageRank URL in crawl with `lastSeen` 45 days old ⇒ stale.
- F4: crawl says 200, agg has a 503 ⇒ mismatch.
- All findings respect the 200-entry cap by ranking.

### Integration tests

`tests/log-analysis-integration.test.ts`:
- Synthetic 100-line log fixture + a small persisted-crawl fixture.
- Mocked DNS resolver returning verified Googlebot for one IP, spoofer for another.
- Assert: complete `LogAnalysisReport`, expected counts, expected
  findings, expected `LOG_*` issues.
- Second case: DNS unavailable (`probeDnsAvailable` returns false).
  Assert: `LOG_DNS_UNAVAILABLE` issue, all hits as `unverifiedBotHits`,
  Layer B still runs.
- Third case: no persisted crawl. Assert: `baselineCrawl: null`,
  no F2/F3/F4 findings.

### Property tests

- Combined-log parser round-trips on randomly generated valid lines.

### Hermeticity

- All log fixtures committed under `tests/fixtures/logs/`.
- DNS verification injected via `dnsResolver` option in `analyzeLogs`.
  Tests pass a mock; production uses `node:dns/promises`.
- CI sets `SEO_AUDIT_NO_DNS=1` to fail loudly if any test escapes the
  mock. (Implementation: when set, the default DNS resolver throws on
  use, forcing tests to inject.)
